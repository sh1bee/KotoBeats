1. Triệu chứng (Symptom)
Các biến môi trường có tiền tố EXPO_PUBLIC_ (như EXPO_PUBLIC_FIREBASE_API_KEY) trong file .env đều trả về undefined (❌ BỊ RỖNG).

Kéo theo hiệu ứng domino gây lỗi khởi tạo Firebase:

Lỗi Auth: Firebase: Error (auth/invalid-api-key).

Lỗi Firestore: Expected first argument to collection() to be a CollectionReference... do Instance của Firebase App không hợp lệ.

Dù đã chạy lệnh xóa cache npx expo start -c nhiều lần, kiểm tra kỹ vị trí và cú pháp file .env nhưng ứng dụng vẫn không nhận biến.

2. Nguyên nhân gốc rễ (Root Cause)
Xung đột cấu hình Metro Bundler: File metro.config.js ở thư mục gốc của dự án sử dụng cấu hình mặc định của React Native thuần CLI (@react-native/metro-config) thay vì của Expo (expo/metro-config).

Cơ chế lỗi: Tính năng tự động quét và nạp các biến môi trường EXPO_PUBLIC_ từ file .env vào process.env là tính năng độc quyền nằm trong bộ biến đổi (transformer) của thư viện expo/metro-config. Khi dùng cấu hình của RN thuần, trình đóng gói hoàn toàn bỏ qua file .env, dẫn đến việc các biến bị trống.

3. Giải pháp khắc phục (Resolution)
Bước 1: Cập nhật lại file metro.config.js để chuyển sang dùng trình đóng gói chuẩn của Expo SDK 56, đồng thời giữ lại phần cấu hình tùy chỉnh cho Async Storage.

Code sau khi sửa:

JavaScript
const { getDefaultConfig } = require('expo/metro-config');

// Khởi tạo cấu hình mặc định chuẩn của Expo
const config = getDefaultConfig(__dirname);

// Giữ lại cấu hình tùy chỉnh extraNodeModules cho async-storage
config.resolver.extraNodeModules = {
  ...config.resolver.extraNodeModules,
  '@react-native-async-storage/async-storage': require.resolve(
    '@react-native-async-storage/async-storage'
  ),
};

module.exports = config;

* **Bước 2 (Tối ưu hóa kèm theo):** Loại bỏ mảng `plugins` bị khai báo trùng lặp (duplicate) trong file `app.json` để nhường quyền quản lý hoàn toàn cho file động `app.config.js`, tránh xung đột khi build native app sau này.
* **Bước 3:** Chạy lệnh `npx expo start -c` để xóa toàn bộ cache cũ của Metro Bundler và buộc hệ thống nạp lại cấu hình mới.

vấn đề ảnh bị "đen" khi chuyển bài hát. Mô tả lỗi: Khi skip sang bài mới (bài B), ảnh của bài B hiển thị bình thường, nhưng ảnh của bài cũ (bài A) trở nên "đen". Nếu quay lại bài A, ảnh của A lại hiển thị bình thường, và bây giờ bài B bị đen.

Lỗi bạn đang gặp phải là một "cạm bẫy" rất kinh điển trong React Native khi kết hợp React.memo với sự thay đổi về Layout (kiểu dáng kích thước).
Màu "đen" mà bạn thấy thực chất không phải ảnh bị lỗi màu, mà đó chính là màu nền backgroundColor: '#1A1A1A' của coverWrap. Ảnh đã bị biến mất (thu nhỏ về 0x0) và để lộ lớp nền ra.
🔍 Nguyên nhân gốc rễ (Root Cause):
Hãy nhìn vào CSS của bạn:
Khi bài hát Active: coverWrap có thêm borderWidth: 2.
Khi bài hát Inactive: coverWrap mất borderWidth (trở về 0).
Sự thay đổi borderWidth làm thay đổi kích thước phần không gian bên trong của coverWrap. Bình thường, khi kích thước parent thay đổi, component con (<Image>) sẽ được layout engine (Yoga) tính toán lại để giãn ra cho vừa.
TUY NHIÊN, bạn lại dùng MemoizedCover chặn đứng hoàn toàn việc re-render của ảnh bằng (prev, next) => prev.uri === next.uri. Hậu quả là:
Bài hát A tắt isActive -> borderWidth về 0.
Parent thay đổi layout, nhưng Component <Image> bên trong hét lên: "Tôi không đổi URI, tôi sẽ không re-render!".
Do từ chối cập nhật layout cùng parent, Native View của <Image> bị lỗi tọa độ/kích thước, dẫn đến sập (collapse) và biến mất -> Lòi màu nền đen ra.

Cách 1: Fix bằng CSS Layout (Nên dùng nếu muốn giữ Memo)
Cách giải quyết rất đơn giản: Đừng làm thay đổi kích thước của parent nữa.
Hãy cho coverWrap luôn luôn có viền (border 2px), nhưng khi KHÔNG active thì viền có màu trong suốt (transparent). Khi active thì đổi màu viền sang xanh.

Cách 2: Xóa bỏ MemoizedCover (Best Practice)
Thực tế, việc bạn bọc React.memo cho <Image> mặc định của React Native là sự tối ưu hóa dư thừa (premature optimization).
Bản thân Native Layer (Android/iOS) của React Native đã tự động cache hình ảnh khi URI giống nhau rồi. Việc Component JS re-render lại thẻ <Image> tốn chi phí cực kỳ nhỏ (vài mili-giây), không hề làm giật app.
Bạn hãy xóa hẳn cái MemoizedCover đi và dùng thẳng <Image>:
code
JavaScript
// Xóa cục MemoizedCover này đi
// const MemoizedCover = React.memo(...) 

// Trong component AnimatedSongItem, gọi thẳng Image:
<View style={[styles.coverWrap, isActive && styles.coverActive]}>
  {item.coverUrl ? (
    <Image source={{ uri: item.coverUrl }} style={styles.cover} fadeDuration={0} />
  ) : (
    <View style={styles.coverPlaceholder}>
       <Ionicons name="musical-notes" size={24} color="#444" />
    </View>
  )}
  {/* ... equalizer ... */}
</View>
💡 Lời khuyên thêm:
Như mình có phân tích ở câu hỏi trước, để app thực sự mượt khi có 100+ bài hát, thay vì dùng <Image> của React Native và tìm cách chặn re-render bằng React.memo, bạn hãy cài thư viện expo-image (nếu dùng Expo) hoặc react-native-fast-image (nếu dùng bare React Native).
Những thư viện này quản lý memory cache của ảnh cực đỉnh, tự động fix luôn mấy lỗi chớp đen ảnh kiểu này mà bạn không cần phải viết thêm một dòng logic chặn render nào cả.
